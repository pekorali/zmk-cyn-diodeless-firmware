# sofle_diodless — ZMK-конфиг (гибридная матрица 5×6 + 4 прямых GPIO)

Готовый конфиг Zephyr/ZMK для split-клавиатуры на **nice!nano v2 (nRF52840)**.

Схема сканирования — **гибридная**:

```
kscan_matrix  5 ROW × 6 COL (11 GPIO, без диодов)  ──┐
                                                     ├──► zmk,kscan-composite ──► matrix-transform ──► keymap
kscan_direct  4 GPIO → 4 клавиши напрямую на GND     ──┘
```

Из-за этого `GUI`, `LOWER`, `ENTER`, `ENC_BTN` физически изолированы от
матрицы — ghosting для них невозможен в принципе.

---

## 0. Про NKRO и матрицу без диодов — важно прочитать

В матрице **без диодов** две клавиши, делящие общий узел (строку или столбец),
замыкают два выхода микроконтроллера друг на друга. Штатный драйвер ZMK
(`zmk,kscan-gpio-matrix`) держит неактивные выходы не в `high-Z`, а
принудительно в HIGH:

```c
gpio_pin_set_dt(out, 1);   // сканируем:  выход -> LOW
...читаем входы...
gpio_pin_set_dt(out, 0);   // не сканируем: выход -> HIGH
```

Из-за этого КЗ возникает между двумя выходами МК, общий узел уезжает в ~Vcc/2,
и **обе клавиши читаются как отпущенные**.

### Решение: собственный kscan-драйвер с high-Z

В этом репозитории лежит драйвер **`zmk,kscan-gpio-matrix-hiz`**:

```
zephyr/src/kscan_gpio_matrix_hiz.c            # сам драйвер
dts/bindings/kscan/zmk,kscan-gpio-matrix-hiz.yaml
zephyr/Kconfig                                # CONFIG_ZMK_KSCAN_GPIO_MATRIX_HIZ
zephyr/CMakeLists.txt                         # сборка драйвера
```

Идея: неактивные выходы переводятся не в HIGH, а в **high-Z** (плавающий вход
без подтяжки):

```c
gpio_pin_configure(port, pin, GPIO_INPUT);   // high-Z
```

Тогда неактивный выход ничего не замыкает, и матрица без диодов работает как
честная NKRO-матрица.

| | Штатный `zmk,kscan-gpio-matrix` | `zmk,kscan-gpio-matrix-hiz` ✅ |
|---|---|---|
| Неактивный выход | HIGH (замыкает) | **high-Z** (не замыкает) |
| Две клавиши одного ряда | ❌ обе отжимаются | ✅ работают |
| Две клавиши одного столбца | зависит от направления | ✅ работают |
| Home-row mods (A+S) | ❌ | ✅ |
| Shift+буква | ❌ | ✅ |
| Ctrl+W, Alt+A, W+S | зависит | ✅ |
| Ток при конфликте | КЗ между выходами МК | **КЗ невозможен** |

### Как это устроено

```
row-gpios = ВЫХОДЫ (строб), col-gpios = ВХОДЫ (PULL_UP)

сканирование строки 0:     row0 = LOW,  row1..row4 = high-Z
  • клавиша в строке 0     -> её столбец читается LOW  (нажата)
  • клавиша в строке 1..4  -> её столбец читается HIGH (не нажата)

состояние покоя:           все 5 выходов = LOW
  • КЗ невозможно (все на одном уровне)
  • нажатая клавиша тянет свой вход в LOW -> срабатывает прерывание
```

Нумерация `(row, col)` при этом не меняется — она совпадает с нумерацией
штатного драйвера (индекс в `row-gpios`, индекс в `col-gpios`), поэтому
`matrix-transform` и `keymap` остаются без изменений.

### Остаточное явление: «призрак» (ghosting)

Даже с high-Z у матрицы без диодов остаётся одно явление. Нажатая клавиша —
это просто **провод между строкой и столбцом**. Три клавиши, образующие
«уголок», замыкают путь:

```
R1 ---[W]--- C2 ---[S]--- R2 ---[D]--- C3
```

Пока сканируется строка 1 (`R1 = LOW`), этот путь тянет и `C3` в LOW — драйвер
видит нажатую клавишу `(1,3)` = **E**, хотя её никто не жал. Именно это и было
проблемой «W + S + D → лишняя E».

**Цифровым сканом это убрать невозможно.** Наборы `{W,S,D}` и `{W,S,D,E}` дают
абсолютно одинаковые напряжения на всех выводах (граф связности один и тот же),
то есть они электрически неразличимы. Никакой алгоритм опроса не сможет их
различить. Единственные настоящие решения — **диоды на PCB** или аналоговое
измерение тока (ADC + резисторы, другой PCB).

Что можно сделать в драйвере — **выбирать наиболее правдоподобную трактовку**:

`CONFIG_ZMK_KSCAN_GPIO_MATRIX_HIZ_GHOST_FILTER` (включён по умолчанию) — фильтр
призраков в `kscan_gpio_matrix_hiz.c`:

* ячейка, которая появилась только потому, что **только что** замкнулась
  цепочка из трёх нажатых клавиш, отбрасывается как призрак;
* клавиши, уже подтверждённые как нажатые, фильтр **никогда** не убирает;
* **воскрешение**: подавленная ячейка, зажатая в момент, когда её
  цепочка-объяснение разрушилась (отпущено достаточно углов квадрата),
  немедленно отдаётся как настоящее нажатие — без отпускания и повторного
  нажатия.

**⚠️ Честное ограничение — эвристика угадывает 50/50.** Наборы `{W,S,D}` и
`{W,S,D,E}` электрически идентичны, но и «зеркальные» тройки тоже: `{`,ESC,1}`
и `` {`,ESC,Q} `` дают одинаковую картину на всех выводах. Для каждого
события-уголка фильтр выбирает одну из равноправных трактовок по порядку
нажатия подтверждённых клавиш; проверка на Python-модели (376 рецептов × 6
порядков = 2256 сценариев, `docs/tools/filter-model-check.py`) показывает:

* в **50%** случаев угадано правильно — лишняя клавиша подавлена (W+S+D → W,S,D);
* в **50%** — зеркально: подавлена **реальная** третья клавиша, а призрак
  прошёл в отчёт (например, гравис + ESC + 1 → вместо единицы приезжает Q).

То есть фильтр убирает примерно половину фантомов, но во второй половине
заменяет лишнюю клавишу на *потерянную + лишнюю*. Это не баг реализации, а
предел цифровой обработки: физического сигнала для различения нет. Решения —
диоды или разводка ревизии 2 (S и F → row4, рецепты 376 → 28).

Остальные ограничения (тоже физика):

* три клавиши «уголком», нажатые **одновременно** (за один опрос) — трактовка
  «нажали всё»: все 4 ячейки уходят в отчёт;
* 4 клавиши квадратом 2×2 (Q+W+A+S) — фильтр не отличит «настоящую четвёртую»
  от призрака: одна клавиша теряется (и воскрешается, когда соседи отпущены).

### Защита от залипания (stuck key)

Механически залипший свитч вечно держит клавишу в HID-отчёте. Драйвер
принудительно отпускает клавишу, непрерывно зажатую дольше
`CONFIG_ZMK_KSCAN_GPIO_MATRIX_HIZ_STUCK_KEY_TIMEOUT_MS` (по умолчанию
300000 мс = 5 минут, `0` — отключено), и игнорирует её до фактического
размыкания контактов. Если какое-то действие требует удержания дольше
лимита — увеличьте таймаут или отключите опцию.

Отключить фильтр (и увидеть «сырую» матрицу) можно так:

```
CONFIG_ZMK_KSCAN_GPIO_MATRIX_HIZ_GHOST_FILTER=n
```

> **Как вернуться к штатному драйверу:** в `sofle_diodless.dtsi` замените
> `compatible = "zmk,kscan-gpio-matrix-hiz"` на
> `compatible = "zmk,kscan-gpio-matrix"` и верните
> `diode-direction = "row2col"`. Работать будет, но вернутся и ограничения
> матрицы без диодов.

### Правая половина

Зеркало левой: те же 15 GPIO, но порядок COL **развёрнут**
(`P1.15, P0.02, P0.29, P0.31, P1.06, P1.04`), ROW4 используется на
позициях col3/col4 (`CTRL`, `ALT`), а блок прямых клавиш сдвинут
на `col-offset = 2` → `(5,2)…(5,5)` = `SPACE, RAISE, RGUI, ENC_BTN`.

> ⚠️ Распиновка правой половины выведена из зеркала левой (в исходном ТЗ
> она не была задана). Если на вашей правой PCB выводы разведены иначе —
> правьте `col-gpios` в `sofle_diodless_right.overlay`, `input-gpios` и
> `sofle_diodless_direct_child { col-offset }` соответственно.

### Конфликты nice!nano, отключённые в dtsi

| Вывод | Что мешает | Что сделано |
|-------|-----------|-------------|
| `P0.20` | I2C0 (SCL) | `&pro_micro_i2c { status = "disabled"; }` |
| `P0.17` | I2C0 (SDA) | OLED переведён на **I2C1** |
| `P1.13`, `P0.10`, `P1.11` | SPI1 (SCK/MOSI/MISO) | `&pro_micro_spi { status = "disabled"; }` |

Из-за этого **RGB-подсветка на WS2812 невозможна без правки dtsi**.

## 3. Раскладка keymap (4 слоя × 72 позиции)

```
┌──────────────────────────────────────┬──────────────────────────────────────┐
│  `   1   2   3   4   5              │  6   7   8   9   0   —            │
│ ESC  Q   W   E   R   T              │  Y   U   I   O   P   BACKSPACE    │
│ TAB  A   S   D   F   G   ★ home     │  H   J   K   L   ;   '     ★ home │
│ SFT  Z   X   C   V   B              │  N   M   ,   .   /   SHIFT       │
│ —   ALT CTRL  —   —   —             │  —   —   —  CTRL ALT  —           │
│ GUI LOW ENT ENC — —    🔴 direct     │  —   —  SPC RAISE GUI ENC 🔴 direct │
└──────────────────────────────────────┴──────────────────────────────────────┘
```

| Слой | Имя | Как включить |
|------|-----|--------------|
| 0 | `QWERTY` | — |
| 1 | `Lower` | удерживать `LOWER` (левый thumb) |
| 2 | `Raise` | удерживать `RAISE` (правый thumb) |
| 3 | `Adjust` | удерживать `LOWER` + `RAISE` |

Энкодеры (если включены):

| Слой | Поворот → | Поворот ← |
|------|-----------|-----------|
| Default | Vol Up / Page Up | Vol Dn / Page Dn |
| Lower | Brightness Up / Next | Brightness Dn / Prev |
| Raise | Right / Down | Left / Up |

### Про SPACE на левой половине

В заданной схеме все 4 прямых GPIO заняты (`GUI`, `LOWER`, `ENTER`, `ENC_BTN`),
поэтому отдельного `SPACE` слева нет — `SPACE` есть только справа.
**Способы добавить:**

1. Распаять ещё один выключатель на свободной позиции матрицы
   `ROW4 × COL5` (`P0.11` × `P1.15`) — это keymap-позиция **53**.
   Затем в `sofle_diodless.keymap` замените в слое 0 строку `pos 48`:
   ```
   /* pos 48 */ &none &kp LALT &kp LCTRL &none &none &kp SPACE ...
   ```
2. Либо временно использовать комбинацию: в ZMK доступны
   `&kp LGUI(SPACE)`, `&kp LALT(SPACE)` и т.п.

## 4. Сборка

### Вариант A — GitHub Actions (рекомендуется)

1. Создайте пустой репозиторий на GitHub и залейте в него эти файлы.
2. Откройте вкладку **Actions** → дождитесь сборки.
3. Скачайте артефакт `firmware`:
   * `sofle-diodless-left.uf2`
   * `sofle-diodless-right.uf2`
4. Прошейте: двойной RESET → USB-накопитель → скопируйте `.uf2`.

Workflow сам определяет корректное имя платы (`nice_nano//zmk` /
`nice_nano_v2` / `nice_nano/nrf52840/zmk`), так что переименование
платы в ZMK его не сломает.

### Вариант B — официальный workflow ZMK

`.github/workflows/build.yml` можно заменить на 4 строки из шаблона ZMK:

```yaml
name: Build ZMK firmware
on: [push, pull_request, workflow_dispatch]
jobs:
  build:
    uses: zmkfirmware/zmk/.github/workflows/build-user-config.yml@v0.3
```

Он прочитает `build.yaml` из корня репозитория.

### Вариант C — локально

```bash
west init -l ./config
west update
west zephyr-export

west build -s zmk/app -d build-left -- \
    -DSHIELD=sofle_diodless_left \
    -DZMK_CONFIG="$PWD/config" \
    -DZMK_EXTRA_MODULES="$PWD"

west build -s zmk/app -d build-right -- \
    -DSHIELD=sofle_diodless_right \
    -DZMK_CONFIG="$PWD/config" \
    -DZMK_EXTRA_MODULES="$PWD"
```

Артефакты: `build-*/zephyr/zmk.uf2`.

## 5. Опции

Всё выключено по умолчанию, кроме NKRO. Раскомментируйте нужное:

| Что | Где | Строки |
|-----|-----|--------|
| NKRO (уже включён) | `config/sofle_diodless.conf` | `CONFIG_ZMK_HID_REPORT_TYPE_NKRO=y` |
| OLED SSD1306 (I2C1, `P0.16`/`P0.17`) | `config/sofle_diodless.conf` | `CONFIG_ZMK_DISPLAY=y` |
| Энкодеры EC11 (`P1.08`/`P1.09`) | `config/sofle_diodless.conf` | `CONFIG_EC11=y`, `CONFIG_EC11_TRIGGER_GLOBAL_THREAD=y` |
| Глубокий сон | `config/sofle_diodless.conf` | `CONFIG_ZMK_SLEEP=y` |

Опции драйвера матрицы (в `zephyr/Kconfig`):

| Что | По умолчанию | Комментарий |
|-----|---------------|-------------|
| `CONFIG_ZMK_KSCAN_GPIO_MATRIX_HIZ` | авто | включается по `compatible` в dtsi |
| `CONFIG_ZMK_KSCAN_GPIO_MATRIX_HIZ_GHOST_FILTER` | **y** | фильтр призраков матрицы без диодов (`=n` — видеть «сырую» матрицу) |
| `CONFIG_ZMK_KSCAN_GPIO_MATRIX_HIZ_STUCK_KEY_TIMEOUT_MS` | 300000 | авто-отпускание клавиши, зажатой дольше лимита (`0` — отключено) |

## 6. Как это работает (для тех, кто будет править)

Позиции композитного kscan:

```
row 0..4  <- kscan_matrix   (0..4, 0..5)
row 5     <- kscan_direct   (5, 0..3)   [левая]
                       (5, 2..5)   [правая, col-offset = 2]
```

Далее `matrix-transform` переводит `(row, col)` в индекс keymap:

* левая половина — без смещения, колонки 0..5;
* правая половина — `col-offset = <6>`, колонки 0..5 → 6..11.

`map` содержит ровно 72 записи и **порядок должен совпадать с порядком
`bindings`** в каждом слое keymap. Если добавляете клавишу — правьте
оба места одновременно.

Позиции матрицы `ROW4 × COL0/COL3/COL4/COL5` (keymap 48, 51, 52, 53)
существуют в transform, но физически не распаяны — они помечены `&none`
и готовы к использованию без изменения прошивки.
