> `CONFIG_ZMK_KSCAN_GPIO_MATRIX_HIZ_STUCK_KEY_TIMEOUT_MS`.

## 1. Что такое «призрак»

Нажатая клавиша в матрице без диодов — это просто **провод между строкой и
столбцом**. Пока сканируется строка `r` (R_r = LOW, остальные строки висят в
high-Z), столбец `c` читается LOW тогда и только тогда, когда от `R_r` до `C_c`
есть путь из нажатых клавиш.

Отсюда главное свойство:

> **Три нажатых угла ЛЮБОГО прямоугольника (2 строки × 2 столбца) дают ложное
> нажатие четвёртого угла.**

Пример для текущей раскладки (S и F в row2 homerow):

```
R1 ---[W]--- C2 ---[S]--- R2 ---[D]--- C3
```

Пока сканируется строка 1, этот путь тянет и `C3` в LOW → драйвер сообщает
«нажата» клавиша `(1,3)` = **E**, хотя её никто не жал.

Разложение по количеству (проверено перебором):

| | значение |
|---|---|
| полных прямоугольников (4/4 угла заняты) | **94** |
| трёхклавишных рецептов ложного нажатия | **376** (94 × 4) |
| из них «соседних» (2×2 из соседних клеток) | 64 |
| «растянутых» (углы разнесены) | 312 |

Полный список по жертвам — в разделе 5.

## 2. Почему это нельзя решить «на 100 %» цифровым сканом

Наборы `{W,S,D}` и `{W,S,D,E}` дают **абсолютно одинаковые напряжения на всех
выводах**: граф связности у них один и тот же (R1–C2–R2–C3, одна компонента).
Значит, никакой алгоритм опроса не сможет их различить — это не дефект
драйвера, а свойство матрицы без диодов.

Различить можно только **аналогово** (измерить ток/сопротивление пути: прямой
ключ ≈ 1 контакт, цепочка ≈ 3 контакта) — это требует АЦП и переделки железа.
Штатное решение — **диоды**.

Вывод: фильтр ниже не «чинит» NKRO, а **выбирает наиболее правдоподобную
трактовку** наблюдения.

## 3. Алгоритм фильтра

### Состояние драйвера

```c
uint32_t confirmed;                 /* реально нажатые клавиши (подтверждённые) */
uint32_t suppressed;                /* ячейки, признанные призраками */
uint32_t observed;                  /* предыдущее "сырое" наблюдение матрицы */
uint32_t press_seq[HIZ_MAX_CELLS];  /* порядок нажатия каждой подтверждённой клавиши */
uint32_t press_counter;
```

### Шаг сканирования

1. **Собрать сырое наблюдение** `raw`: при сканировании строки `i` читаются все
   столбцы; нажатые клетки кладутся в битовую маску (индекс ячейки —
   `col * rows + row`, как в `matrix_state`).
2. **Отбросить отпущенное**: `confirmed &= raw; suppressed &= raw;`
3. **Новые ячейки**: `fresh = raw & ~observed` — то, что появилось только что.
4. **Перебор кандидатов** (по возрастанию индекса ячейки). Кандидат — ячейка,
   которая новая и ещё не подтверждена:
   - если её удаление ломает объяснение наблюдения
     (`hiz_matrix_closure(real & ~bit) != raw`) → ячейка настоящая;
   - если ячейку нельзя объяснить цепочкой из трёх клавиш
     (`hiz_ghost_explainable(...)`) → ячейка настоящая;
   - иначе ячейка — **призрак**: `real &= ~bit; suppressed |= bit;`
5. **Подтвердить** новые реальные клавиши: присвоить им `press_seq[i] =
   press_counter++`.
6. **Отдать результат в дебаунсер** (`zmk_debounce_update`) — дебаунсер видит уже
   очищенную матрицу, поэтому призрак никогда не доходит до HID.

### Правило «цепочки» (ключевое)

Ячейка `(r,c)` считается призраком, если её объясняют три клавиши

```
K1 = (r, c1) --- K2 = (r2, c1) --- K3 = (r2, c),   r2 != r, c1 != c
```

при трёх условиях:

1. все три клавиши есть в наборе «реальных»;
2. **в цепочке есть клавиша, которая появилась только что** (`fresh`) — иначе
   цепочка была бы замкнута давно и призрак появился бы раньше;
3. **уже подтверждённые клавиши цепочки нажаты в том же порядке** (по
   `press_seq`).

Условие 2 — физическое обоснование: призрак появляется ровно в момент, когда
замыкается цепочка, то есть последней нажатой клавишей цепочки. Условие 3 —
эвристика для разрешения неоднозначности (см. п. 6).

### Вспомогательные функции

| функция | назначение |
|---|---|
| `hiz_matrix_closure(mask, rows, cols)` | какие ячейки читаются нажатыми, если нажаты ячейки из `mask` (union-find по строкам/столбцам) |
| `hiz_ghost_explainable(cell, ...)` | есть ли для ячейки подходящая цепочка (перебор `c1 × r2`) |
| `hiz_filter_ghosts(dev, raw)` | основной фильтр, возвращает «чистую» маску |

Опция: `CONFIG_ZMK_KSCAN_GPIO_MATRIX_HIZ_GHOST_FILTER` (в `zephyr/Kconfig`),
по умолчанию **y**. Значение `n` — видеть «сырую» матрицу без фильтра.

### Воскрешение при разрыве цепочки (добавлено 22.10.2026)

Подавленная ячейка остаётся подавленной, пока её можно объяснить цепочкой из
трёх реальных клавиш. Когда цепочка разрушилась (углы квадрата отпущены), а
ячейка всё ещё зажата и читается нажатой — она настоящая: фильтр немедленно
отдаёт её как нажатие (`hiz_filter_ghosts`, блок «ВОСКРЕШЕНИЕ»).

Особенности физики квадрата: пока держатся 3 из 4 углов, четвёртый читается
нажатым даже после отпускания *одного* из углов (обратный путь через зажатый
«призрак»-кандидат). Воскрешение срабатывает, когда разрушено достаточно
цепочки — обычно после отпускания двух углов.

### Защита от залипания (добавлено 22.10.2026)

`CONFIG_ZMK_KSCAN_GPIO_MATRIX_HIZ_STUCK_KEY_TIMEOUT_MS` (по умолчанию
300000 мс, `0` — отключено): клавиша, непрерывно зажатая дольше лимита,
принудительно отпускается и ставится в карантин до фактического размыкания
контактов. События клавиши в карантине подавляются, повторных нажатий нет;
вклад в `continue_scan` не вносится (клавиатура может уснуть, но учтите:
физический провод залипшего свитча всё равно может будить матрицу).

## 4. Проверка

Алгоритм проверялся двумя независимыми способами.

**а) Модель.** Написана Python-модель электрики матрицы (union-find по графу
«нажатые клавиши = рёбра»), в ней перебирались все комбинации.

**б) Сверка C-реализации с моделью.** C-код был транслитерирован в Python

## 6. Что фильтр НЕ может (и это физика, а не баг)

Неоднозначность неустранима: `{W,S,D}` и `{W,S,D,E}` неразличимы. Практические
следствия:

* **три клавиши «уголком», нажатые одновременно** (за один опрос) — фильтр
  выбирает одну из двух равноправных трактовок (угадывает);
* **четыре клавиши квадратом 2×2** (например Q+W+A+S) — фильтр не сможет
  отличить «настоящую четвёртую» от призрака и одну клавишу не покажет;
* клавиша, нажатая **после** того, как её ячейка уже стала призраком, не
  будет засчитана (призрак исчезнет только когда разорвётся цепочка).

В новой ревизии платы (S и F уходят в row4) игровые комбинации становятся чистыми
**в схеме**, без помощи фильтра: C S D, W E S D, W A S D, W E S, Q W A, X D C,
A S D, W S D, S D F, D F R, Z X C, X C V — ложных нажатий нет.
